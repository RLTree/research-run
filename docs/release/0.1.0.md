# Research Run 0.1.0 Release Contract

## Release class

`0.1.0` is an unreleased technical-preview candidate for individual graduate
researchers and research engineers working in local Git-backed projects. It is
not a declaration of general Product Fitness, scientific validity, adoption, or
research impact.

## Positive claims permitted at release

- The named release artifact corresponds to the exact reviewed Git commit.
- The offline Rust CLI preserves its versioned JSON authority and enforces the
  documented confinement, boundedness, publication, recovery, and signed-review
  rules on the verified platforms.
- The packaged and installed CLI completes the documented synthetic journey.
- A signed review records scoped human assessment of the exact workspace
  evidence graph.

## Claims explicitly not made

- A `supported` assessment is not general scientific truth.
- Ledger validation is not replication, peer review, or validation of methods,
  measurements, analyses, interpretations, or conclusions.
- A valid detached signature is not proof of personhood or biological identity.
- Synthetic and agent-operated journeys are not audience-bound Product Fitness.
- First-use completion is not continuance, daily-driver usefulness, scientific
  impact, or outcome improvement.

## Candidate gates

Before release authorization:

1. The semantic source namespace, source gates, coverage, dependency/security,
   bounded mutation, package/install, installed journey, and release-candidate
   checks pass on one clean exact commit.
2. `CHANGELOG.md`, `SECURITY.md`, the license, schemas, and quickstart describe
   that same candidate.
3. Product Fitness evidence is either a valid external receipt plus
   actor-disjoint disposition or remains explicitly withheld.
4. An owner-controlled key signs the canonical candidate-authorization request.
   Verification records configured-key control only.
5. The required independent material reviews sign off on the exact candidate,
   and GitHub checks settle green.

This contract does not authorize a merge, tag, package publication, or GitHub
release. A publication contract must separately name the channel, artifact
digests, rollback, and human authority.
