## Success contract

1. **Semantic source namespace:** only Cargo-required crate roots remain directly
   under `src/`; every product module and private unit test lives beneath the
   behavior it owns, and a red/green standards fixture prevents regression.
2. **Product Fitness:** a consenting target researcher can run the
   exact-candidate unfamiliar-project journey under a written observation
   protocol. A machine-validated receipt records completion, errors, recovery
   burden, accessibility, cognitive load, and the claim ceiling. Synthetic,
   agent-operated, and package journeys remain non-substitutes.
3. **Human authority:** the owner can prepare and approve a detached release
   authorization with the separately controlled Ed25519 key. Verification proves
   control of the configured key and exact request, not personhood, intent
   outside the signed text, or biological identity.
4. **Scientific truth:** release language states that Research Run preserves
   scoped evidence, observations, interpretations, and signed review decisions.
   Validation and a `supported` assessment do not establish general scientific
   truth, replication, real-world validity, or impact.
5. **Release candidate:** version, license, changelog, security reporting,
   package/install journey, source gates, exact candidate identity, GitHub
   checks, and material reviews are bound without publishing externally.
6. **Delivery:** coherent commits update
   `codex/pr-review-automation`; release, tag, merge, scientific truth,
   continuance, and any unobserved Product Fitness claim remain withheld.

## Inventory scalability successor

The current `main` inventory authority is unsuitable for large scientific homes:
the scanner owns fixed 2,048-entry, 64 MiB-per-file, and 512 MiB-total limits,
recursively treats nested Research Run state as ordinary material, and has no
truthful representation for an intentionally uninspected artifact root. The
focused baseline test
`workspace::tests::inventory_expanded::inventory_count_and_byte_budgets_accept_the_limit_and_reject_the_next_unit`
passed on `fe3466647e207c642a98e5c80f3f569b62b175df`, confirming those old limits
are executable current behavior rather than documentation drift.

Branch `codex/inventory-policy` owns the smallest structural repair. It will add
one embedded, versioned inventory policy; retain policyless legacy behavior;
default new indexed scans to 20,000 entries, 2 GiB per file, and 8 GiB total;
permit explicit `u64` totals of 64 GiB and above; and add exact reference-only
and child-workspace boundaries. Reference-only descendants and child materials
remain explicitly uninspected. Apply and recovery must rescan with the accepted
policy and publish one atomic canonical inventory. Mutation remains skipped;
Rust verification stays serialized. This successor may produce clean feature
branch commits, but it may not merge, tag, publish, release, or raise Product
Fitness or scientific-truth claims.
