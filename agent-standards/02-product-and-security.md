# Product And Security

- Parse untrusted input before effects; fail authorization and ambiguous state
  closed. Preserve workspace confinement, no-clobber atomic publication, typed
  recovery, bounded resources, and deterministic serialization.
- Only explicit human review may promote a claim. Derived output and receipts
  cannot raise authority.
- Never persist secrets, raw private messages, human-subject data, unpublished
  raw datasets, or biosafety-sensitive operational detail as routine proof.
- A dependency addition must justify license, provenance, attack surface,
  maintenance, runtime/build cost, alternatives, and rollback.
- Reliability is correctness. Changes to retry, idempotency, interruption,
  recovery, paths, or cleanup require focused negative evidence.
- Product claims require the installed public journey and representative
  recovery behavior. Correct source or a passing mock is not a user outcome.
